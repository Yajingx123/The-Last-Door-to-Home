# Feasibility Notes v0.1

## 1. Purpose
This document evaluates whether the current planned scope of *The Last Door to Home* is feasible to implement in Unity within the coursework timeframe.

## 2. Core Systems Needed for First Playable Version
- 2D player movement and collision
- room transition system
- object interaction system
- clue/message trigger system
- simple puzzle logic
- equipment selection system
- branching ending conditions
- boss encounter logic

## 3. Essential Features
These features are required for the first playable version:
- one playable route from the dorm room to the teleportation room
- basic room exploration
- interactable objects and clues
- at least one puzzle controlling progression
- equipment choice before the final encounter
- one boss encounter with failure condition
- at least one complete ending

## 4. Optional / Removable Features
These features can be reduced or removed if the scope becomes too large:
- one endings (cycle)
- full dialogue/message set
- complex animations
- advanced visual effects
- complex boss attack patterns
- multiple puzzles
- extra optional rooms or objects

## 5. Main Technical Risks in Unity
- boss fight may take longer than expected
- too many scripted events may become hard to manage
- dialogue and clue triggers may become messy without a clear state system
- balancing equipment speed changes may require testing
- too much story content may slow down implementation

## 6. Minimum Viable Vertical Slice
The minimum viable version will include:
- one small connected map
- one playable route
- basic player movement
- object interaction
- one puzzle
- one equipment choice
- one boss encounter
- one working ending

This version should still demonstrate the main experience of the game: exploration, clue-based progression, decision-making, and survival.

## 7. Feasibility Decision
The current scope is feasible if the game remains small and focused.

The project should prioritise:
1. core interaction system
2. puzzle progression
3. boss encounter
4. one complete playable path

Additional endings, extra dialogue, and visual polish should only be added after the first playable version works.
